# Альфред — правила проекта

Telegram-бот «Альфред» (дворецкий 🎩, обращается к пользователю «Сэр»/«Мэм»).
Python + aiogram, мозг — GigaChat, хостинг — Railway (деплой из GitHub).

## Общение с владельцем
- Владелец проекта не программист: объясняй просто, по-русски, без лишнего жаргона.
- В конце каждой задачи пиши раздел **«Что проверить в боте»** (см. «Проверка в боте» ниже). Владелец не хочет
  рутинной ручной проверки — всё, что можно проверить автоматически, проверяй тестами и самопроверкой.

## Тесты — после каждого изменения
Запускай оба прогона, все тесты должны проходить:

```powershell
python -m pytest
$env:ALFRED_TEST_ENCRYPT='1'; python -m pytest; Remove-Item Env:ALFRED_TEST_ENCRYPT
```

Если что-то падает — чини, а не отключай тест. Не считай задачу готовой, пока оба прогона не зелёные.

Новое поведение бота покрывай тестом. Всё, что связано с Telegram (очередь, кнопки, длинные ответы, ошибки),
проверяй сквозными тестами в `tests/test_telegram_flow.py`. Если появляется или меняется то, что понимает GigaChat,
добавь фразу в `STEPS` самопроверки `alfred/core/selftest.py` (с проверкой того, что записалось, и `ideal` — как
фразу должен понять GigaChat; `tests/test_selftest.py` проверит, что все шаги проходят при идеальном понимании).

Python на этом компьютере может не находиться в PATH сессии — перед запуском обнови PATH:
`$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')`

После Push GitHub сам прогоняет тесты (`.github/workflows/tests.yml`).

## Проверка в боте
Три автоматические ступени: тесты у меня → тесты в GitHub (Railway с «Wait for CI» не запустит сломанное) →
🧪 самопроверка: после обновления Альфред сам прогоняет живые фразы через настоящий GigaChat и присылает
владельцу итог («✅ 17 из 17» или список ❌). Вручную — `/selftest` или кнопка в ⚙️ Система.

В разделе «Что проверить в боте» в конце задачи:
- главное — дождаться сообщения самопроверки после обновления; если там ❌ — владелец присылает его мне;
- руками проси проверить только то, что автоматикой не проверить (как выглядит новый экран или кнопка), 1–2 пункта.

## Версия
При каждом изменении кода бота поднимай версию в двух местах одинаково:
- `alfred/__init__.py` → `VERSION = "…"`
- `README.md` → заголовок `# 🎩 Альфред — этап 8 (версия …)`

Обычно +0.01 (например, 8.28 → 8.29). Если появилась новая возможность — допиши её в список «Что умеет» в README.md.

## Секреты
`TELEGRAM_TOKEN`, `OWNER_ID`, `GIGACHAT_AUTH_KEY`, `DATA_KEY`, `UNI_LOGIN`, `UNI_PASSWORD` хранятся **только**
в Railway → Variables (`UNI_GROUP` — не секрет, но тоже там). Пароль вуза не логировать и не показывать в сообщениях.
- Никогда не вписывай их значения в код, тесты, README или другие файлы репозитория.
- Никогда не делай так, чтобы их можно было задать или посмотреть через чат бота.
- Читать их — только через переменные окружения (см. `alfred/config.py`).

## Git
- Сам **не делай push** (и не трогай удалённый репозиторий). Коммит и Push владелец делает в GitHub Desktop.
- Railway разворачивает бота автоматически после Push.

## Устройство проекта
- `main.py` — точка входа (Start Command на Railway: `python main.py`).
- `alfred/config.py` — настройки из переменных окружения.
- `alfred/brain` — разбор обычной речи через GigaChat.
- `alfred/handlers` — обработка сообщений и кнопок.
- `alfred/database` — хранилище (на Railway — Volume `/data`, опционально шифрование `DATA_KEY`).
- `alfred/notifications` — напоминания, сводки, проверки по расписанию (по местному времени каждого; обычно — Москва).
- `alfred/core/selftest.py` — 🧪 самопроверка после обновления.
- `alfred/services` — внешние сервисы (погода Open-Meteo, курсы ЦБ и т.п.).
- `alfred/ui` — клавиатуры и тексты.
- `tests/` — pytest; `ALFRED_TEST_ENCRYPT=1` гоняет тесты с включённым шифрованием базы.
